# 雅思工坊架构

## 产品边界

当前产品面向雅思学习，首页包含词汇、听说读写及题库／语料／复习，一级导航为学习、查询、我的。题库category是用户分类，track保留general、english、postgraduate、ielts以兼容既有资料，默认新内容为ielts；不因界面聚焦雅思而删除历史业务数据。工作工具专属前端已经退休，共享的历史文件读取与导出实现仍保留。

查询由独立前端模块和同账号保护下的lookup路由完成。先查本人可见词库和语料，无完整词条时调用服务端配置的DeepSeek补充。追问使用有界上下文，只有明确引用的单条本人语料加入请求；查询与追问不自动写回内容。页面离开后销毁监听并忽略迟到响应，防止结果覆盖其他页面。原生更新／服务器／关于集中在个人中心，网页提供版本信息和安装包下载入口。

## 运行结构

浏览器通过同端口静态资源和 /api 访问 Node.js Web。Web 负责账号认证、文件提取、题目验证、随机组卷与标准答案判分。MySQL 保存关系表；可选 Worker 从 processing_jobs 领取无标准题目的资料生成任务，并调用已配置的 OpenClaw。生成结果回到用户预览，确认后才入库。

Web 是单进程服务，维护内存工作状态并以事务增量写回 MySQL；因此 PM2 必须保持 instances:1，不应并排运行多个连接同一数据库的 Web 实例。Worker 只负责任务表，不修改 Web 的题库工作状态。写接口需等待持久化完成再反馈成功。

## 账号与归属

- 统一会话使用随机 token，仅哈希持久化；所有账号都可管理自己的题库并学习。
- 旧管理员 HTTP 接口关闭。服务端 APP_USERNAME / APP_PASSWORD 创建初始账号；兼容读取旧 ADMIN_* 配置。
- 旧 owner_id 为空的题库由初始账号接管；已归属其他账号的私有题库不转移。
- 系统种子词条 owner_id 为空，对所有账号只读；个人词表导入写入账号 owner_id。
- 答卷、成绩、收藏、翻译记录、草稿与学习日志始终以账号 ID 检查访问权限。

## 数据迁移

database/schema.sql 创建基础表；src/db/migrate-v6.js 检查字段是否已存在后增量增加分类、词条归属、草稿、种子初始化标志，并将学习方向扩展为 VARCHAR。旧方向值留在数据库中，由兼容过滤隔离。原 app_state 保留用于核对。

从 JSON 导入 MySQL 使用 scripts/import-legacy-json.js，覆盖题库、考试、成绩、账号、词条、收藏、复习进度、译文和学习笔记；旧会话不导入。原数据必须先备份，备份不进入发布包。

删除题库时解绑 bank_id 并保留独立答卷快照。错题聚合保留原文、答案及语言，防止阅读练习脱离材料；考试中不返回标准答案或解析。英语填空匹配保留单词之间的空格，不把不同词组当成同一个答案。

## 内容

src/seed-vocabulary.js 是 90 个原创双语起步词条。src/seed-study.js 是 4 篇原创阅读材料、12 道标准答案题。阅读种子每个账号仅初始化一次；删除后的内容不会再次自动添加。IELTS 写作/口语笔记不自动判分，练习正确率不换算官方 band。
